# 03 文档库契约

本契约定义 agent 产出、flDoc 读取的文档库格式。契约标识 `fldoc.library/1`。agent 侧的执行指令见 [04-导入提示词.md](04-导入提示词.md)，两者必须保持一致。

## 1. 两种库格式

| 格式 | 识别条件 | 能力 |
|------|----------|------|
| 契约库 | 库目录下存在 `manifest.json` | 多版本、自定义目录树、中英双语、符号索引、增量更新、来源 URL 映射 |
| 纯 Markdown 库 | 无 `manifest.json`，目录内（递归）至少一个 `.md` | 单版本 `default`；目录按文件夹结构自然排序；标题取首个 `#`，否则用文件名；无符号索引（函数搜索走 rg 兜底） |

纯 Markdown 库可通过命令「文档库: 为此文件夹生成 manifest」转为契约库：生成的 manifest 采用「平铺版本」模式（见 2.2），不移动、不修改任何 .md 文件。

## 2. 目录结构

### 2.1 标准结构（agent 产出使用）

```
<库根目录>/
  <libId>/                         库目录，名称必须等于 manifest.id
    manifest.json                  库清单（最后写入）
    icon.png                       可选，库图标，建议 128x128
    <versionId>/                   每个版本一个目录；单版本也必须有一个版本目录，如 latest
      pages/                       页面
        index.md                   版本首页
        index.en.md                首页英文原文（翻译时才有）
        introduction/
          getting-started.md
          getting-started.en.md
      assets/                      图片等资源，中英页面共用
        3f2a9c1b-architecture.png
      symbols.json                 符号索引（可选但强烈建议）
      crawl-state.json             增量抓取状态（agent 用，flDoc 只读不依赖）
      crawl-report.md              最近一次抓取报告（agent 写，flDoc 可在校验中显示）
```

### 2.2 平铺版本（仅用于纯 Markdown 库转换）

manifest 中版本的 `dir` 为 `"."`，页面路径直接相对库目录。agent 产出不使用此模式。

### 2.3 命名规则

| 对象 | 规则 |
|------|------|
| libId | `^[a-z0-9][a-z0-9-]{0,63}$` |
| versionId | `^[A-Za-z0-9][A-Za-z0-9._-]{0,31}$`，如 `3.x`、`2.6.1`、`latest` |
| 页面路径 | 相对版本目录，`pages/` 开头；路径段 `^[a-z0-9][a-z0-9._-]*$`；中文页 `.md`，原文页同名加 `.en.md` |
| 资源文件 | `assets/<sha256 前 8 位>-<原文件名小写 kebab>.<ext>` |
| 编码 | UTF-8 无 BOM，换行 LF |

页面路径由来源 URL 推导：去掉 `scope` 前缀后的路径段，末尾 `/` 或空路径映射为 `index.md`，去掉 `.html` 等扩展名。

## 3. manifest.json

```json
{
  "schema": "fldoc.library/1",
  "id": "riverpod",
  "name": "Riverpod",
  "description": "Flutter/Dart 响应式缓存与状态管理框架",
  "homepage": "https://riverpod.dev",
  "icon": "icon.png",
  "sourceLanguage": "en",
  "displayLanguage": "zh-CN",
  "defaultVersion": "3.x",
  "updatedAt": "2026-11-22T16:00:00+08:00",
  "generator": "agent:claude",
  "versions": [
    {
      "id": "3.x",
      "label": "3.x（最新）",
      "dir": "3.x",
      "sourceUrl": "https://riverpod.dev/docs/introduction/getting_started",
      "scope": "https://riverpod.dev/docs/",
      "crawledAt": "2026-11-22T15:40:00+08:00",
      "pageCount": 86,
      "translated": true,
      "toc": [
        { "title": "首页", "page": "pages/index.md" },
        {
          "title": "入门",
          "icon": "Rocket",
          "children": [
            { "title": "快速开始", "page": "pages/introduction/getting-started.md" },
            { "title": "为什么选择 Riverpod", "page": "pages/introduction/why-riverpod.md" }
          ]
        },
        {
          "title": "核心概念",
          "page": "pages/concepts/index.md",
          "children": [
            { "title": "Provider", "page": "pages/concepts/providers.md" }
          ]
        }
      ]
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| schema | 是 | 固定 `fldoc.library/1` |
| id | 是 | 等于库目录名 |
| name | 是 | 显示名 |
| description | 否 | 卡片描述，中文 |
| homepage | 否 | 官网 |
| icon | 否 | 相对库目录的图片路径 |
| sourceLanguage | 是 | 原文语言 BCP 47，如 `en`、`zh-CN` |
| displayLanguage | 是 | 主显示语言，固定 `zh-CN` |
| defaultVersion | 是 | 必须是 versions 中的某个 id |
| updatedAt | 是 | ISO 8601 带时区 |
| generator | 否 | 生成者标识 |
| versions[].id / label / dir | 是 | dir 等于 id（平铺模式为 `.`） |
| versions[].sourceUrl | 是 | 抓取起点 |
| versions[].scope | 是 | URL 前缀，只抓取此前缀下的页面 |
| versions[].crawledAt | 是 | 本版本最近一次抓取时间 |
| versions[].pageCount | 否 | 页面数（中文页计数） |
| versions[].translated | 是 | 是否存在 `.en.md` 原文 |
| versions[].toc | 是 | 目录树 |

toc 节点：

| 字段 | 说明 |
|------|------|
| title | 必填，中文显示标题 |
| page | 可选，页面路径；章节节点可以同时有 page 和 children |
| children | 可选，子节点数组 |
| icon | 可选，Fluent 图标名，仅顶层节点在图标栏模式下使用 |

toc 中的节点顺序就是侧边栏顺序，应与原站导航一致。每个页面在 toc 中最多出现一次。

## 4. 页面文件

### 4.1 front matter

中文页（`xxx.md`）：

```markdown
---
title: 快速开始
source_url: https://riverpod.dev/docs/introduction/getting_started
source_lang: en
lang: zh-CN
translated: true
original: getting-started.en.md
fetched_at: 2026-11-22T15:32:10+08:00
source_sha256: 9b1c...e4
tags: [入门, 安装]
---
```

原文页（`xxx.en.md`）：

```markdown
---
title: Getting started
source_url: https://riverpod.dev/docs/introduction/getting_started
lang: en
fetched_at: 2026-11-22T15:32:10+08:00
source_sha256: 9b1c...e4
---
```

| 字段 | 必填 | 说明 |
|------|------|------|
| title | 是 | 页面标题（中文页为中文） |
| source_url | 是 | 原始 URL，用于外链本地映射与去重 |
| lang | 是 | 本文件语言 |
| source_lang | 中文页必填 | 原文语言 |
| translated | 中文页必填 | 是否为译文 |
| original | translated 为 true 时必填 | 原文文件名，与本文件同目录 |
| fetched_at | 是 | 抓取时间 |
| source_sha256 | 是 | 原文 Markdown 正文（不含 front matter）的 SHA-256，用于增量判断 |
| tags | 否 | 标签 |

原文本身是中文时：只有 `xxx.md`，`translated: false`，不生成 `.en.md`。

### 4.2 正文规则

- 正文第一行起为内容，不重复写 `# 标题`（标题由 front matter 显示）；正文标题从 `##` 开始。
- 每个标题末尾带显式锚点 `{#id}`：`## 安装依赖 {#install-dependencies}`。
  - id 规则：`^[a-z0-9][a-z0-9-]*$`，由英文原标题转为小写 kebab；同页内唯一，重复时加 `-2`、`-3`。
  - 中文页与原文页对应标题使用相同 id，保证切换语言、引用、符号跳转一致。
  - 无显式锚点时（纯 Markdown 库），flDoc 按 GitHub 规则生成：转小写，删除除字母数字（含中文）、空格、`-`、`_` 外的字符，空格转 `-`，重复加 `-1`、`-2`。
- 代码块：必须是围栏代码块，标注语言（`dart`、`yaml`、`bash`、`json` 等），代码与代码内注释保持原文不翻译。
- 提示块：统一转换为 GitHub Alerts：

  ```markdown
  > [!WARNING]
  > 内容
  ```

  原站的 admonition / callout（如 `:::tip`、Docusaurus、MkDocs、VitePress 样式）都映射为 NOTE / TIP / IMPORTANT / WARNING / CAUTION 之一。
- 表格：GFM 表格；复杂合并单元格表格降级为列表。
- 任务列表：`- [ ]` / `- [x]`。
- 公式：行内 `$...$`，块级独占行 `$$ ... $$`。
- 图表：原站 Mermaid 源码保留为 ```mermaid 代码块；图片形式的图表按图片处理。
- 选项卡（Tabs，如多语言代码示例）：展开为依次排列的小节，每个选项卡用 `**选项卡名**` 加粗标题标注。
- 去除：导航栏、页脚、侧栏、广告、Cookie 提示、「编辑此页」、上一页/下一页按钮、版本横幅等页面框架内容。
- 允许的内联 HTML 仅限：`<kbd>`、`<sub>`、`<sup>`、`<br>`、`<details>`、`<summary>`；其余转为 Markdown 或纯文本。

### 4.3 链接

- 指向已抓取页面的链接改写为相对路径，相对当前文件：`[Provider](../concepts/providers.md#what-is-a-provider)`。中文页链接到中文页，原文页链接到原文页。
- 指向未抓取页面或站外的链接保留绝对 URL。
- 页内锚点使用 `{#id}` 中的 id。

### 4.4 图片

- 下载到版本目录 `assets/`，正文中以相对当前文件的路径引用，如 `![架构图](../../assets/3f2a9c1b-architecture.png)`。
- 中文页与原文页引用同一资源文件。
- 图片 alt 文本在中文页中翻译。
- SVG 保留为 .svg；单个资源超过 10 MB 时不下载，保留远程链接并在 crawl-report.md 中记录。

## 5. symbols.json

```json
{
  "schema": "fldoc.symbols/1",
  "symbols": [
    {
      "name": "watch",
      "qualifiedName": "Ref.watch",
      "kind": "method",
      "signature": "T watch<T>(ProviderListenable<T> provider)",
      "page": "pages/concepts/reading.md",
      "anchor": "using-refwatch",
      "summary": "监听 provider，值变化时重建",
      "aliases": ["ref.watch"]
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| name | 是 | 短名 |
| qualifiedName | 否 | 带所属类型的全名 |
| kind | 是 | `class` / `function` / `method` / `property` / `constructor` / `enum` / `typedef` / `extension` / `mixin` / `widget` / `annotation` / `cli` / `config` / `other` |
| signature | 否 | 签名原文 |
| page | 是 | 讲解此符号最主要的中文页路径 |
| anchor | 否 | 页内锚点 id |
| summary | 否 | 一句话中文说明 |
| aliases | 否 | 别名、常见写法 |

收录原则：文档中有专门讲解或代码示例的公开 API；同一符号在多页出现时取讲解最详细的一页，其余页可作为额外条目（相同 qualifiedName、不同 page）。

## 6. crawl-state.json

agent 增量抓取用，flDoc 不依赖其内容，仅在校验时检查格式。

```json
{
  "schema": "fldoc.crawlstate/1",
  "scope": "https://riverpod.dev/docs/",
  "pages": {
    "https://riverpod.dev/docs/introduction/getting_started": {
      "page": "pages/introduction/getting-started.md",
      "sourceSha256": "9b1c...e4",
      "etag": "\"abc\"",
      "lastModified": "Sat, 21 Nov 2026 10:00:00 GMT",
      "fetchedAt": "2026-11-22T15:32:10+08:00",
      "status": "ok"
    }
  },
  "assets": {
    "https://riverpod.dev/img/architecture.png": "assets/3f2a9c1b-architecture.png"
  }
}
```

`status` 取值：`ok` / `removed`（源站已不存在，已从 toc 移除，文件保留）/ `failed`（抓取失败）。

## 7. URL 规范化（去重与本地映射共用）

1. 协议统一为 `https`，主机名转小写，去掉 `www.` 前缀。
2. 去掉 fragment（`#...`）；去掉 query，除非 query 决定页面内容（agent 在 crawl-state 中按原样记录，flDoc 映射时同时尝试保留与去除 query 两种形式）。
3. 去掉末尾 `/`、`index.html`、`.html` 扩展名。
4. 路径中的百分号编码按 RFC 3986 规范化。

## 8. 写入顺序与原子性

agent 写入顺序：资源 → 原文页 → 中文页 → symbols.json → crawl-state.json → crawl-report.md → manifest.json（最后）。

flDoc 侧：监听防抖 1.5 秒；manifest.json 解析失败时保留上一次成功加载的状态并在卡片上显示警告，下次变化时重试。

## 9. 校验规则

「校验文档库」与 agent 自检使用同一份规则。级别：E 错误（影响使用）、W 警告。

| 编号 | 级别 | 规则 |
|------|------|------|
| V01 | E | manifest.json 是合法 JSON，schema 为 `fldoc.library/1` |
| V02 | E | id 符合命名规则且等于目录名；跨根目录不重复 |
| V03 | E | defaultVersion 存在于 versions；版本 id 唯一；dir 目录存在 |
| V04 | E | toc 引用的 page 文件存在，且路径解析后不越出版本目录 |
| V05 | W | 页面在 toc 中出现多次 |
| V06 | W | `pages/` 下存在 toc 未引用的中文页（孤儿页） |
| V07 | E | 页面 front matter 可解析且必填字段齐全 |
| V08 | E | `translated: true` 时 original 文件存在；原文页 source_url 与中文页一致 |
| V09 | W | 中文页与原文页的锚点 id 集合不一致 |
| V10 | W | 同页锚点 id 重复，或标题缺少 `{#id}`（契约库） |
| V11 | E | 相对链接目标文件不存在 |
| V12 | W | 相对链接锚点在目标页中不存在 |
| V13 | E | 引用的本地图片不存在 |
| V14 | W | 代码块未标注语言 |
| V15 | E | symbols.json 格式错误；symbol 的 page 不存在 |
| V16 | W | symbol 的 anchor 在 page 中不存在 |
| V17 | W | 中文页正文中英文字符占比超过 60%（排除代码块、行内代码、链接 URL），疑似漏翻译 |
| V18 | W | 存在 HTML 白名单外的标签 |
| V19 | W | 多个页面的 source_url 规范化后相同（重复抓取） |
| V20 | W | 文件编码非 UTF-8 或含 BOM |

## 10. 契约版本演进

- 新增可选字段不升版本；flDoc 忽略未知字段。
- 破坏性变更升级为 `fldoc.library/2`，flDoc 同时支持旧版本读取，并在校验中提示可升级。
